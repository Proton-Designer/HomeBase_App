# HomeBase Web Deployment

The same Expo Router app that ships to iOS/Android also ships as a deployable web SPA. Build runs `expo export --platform web`, output goes to `dist/`.

## Local preview

```bash
npm run preview:web      # build then serve at http://localhost:4173
# or, separately
npm run build:web        # writes ./dist
npm run serve:web        # serves ./dist with SPA fallback
```

## Vercel

The `vercel.json` config builds from the monorepo root. From `apps/mobile/`:

```bash
npx vercel --prod
# or
npm run deploy:vercel
```

Vercel will:
1. `cd ../..` and `npm install --legacy-peer-deps` (resolves the workspace)
2. Run `npx expo export --platform web --output-dir dist`
3. Serve `dist/` with `/(.*)` rewriting to `/index.html` so client routes work
4. Cache `_expo/static/*` for one year (immutable hashed files)

**Project Settings on Vercel**
- Root Directory: `Marketplace_MVP/app/apps/mobile`
- Framework Preset: **Other**
- (Build/Install/Output commands all read from `vercel.json`)

## Netlify

`netlify.toml` lives next to `vercel.json`. From the repo root:

```bash
netlify deploy --prod --dir=Marketplace_MVP/app/apps/mobile/dist
# or, after building
cd Marketplace_MVP/app/apps/mobile && npm run deploy:netlify
```

## Cloudflare Pages

Use the Vercel config as a template — same build command, output `dist/`, and an SPA `_redirects` file is auto-generated by Pages from the rewrites pattern. If not, drop a `dist/_redirects` file with:

```
/*  /index.html  200
```

## What ships in the web bundle

- The **same screens and stores** as the native app — all of `(homeowner)`, `(provider)`, `(tech)`, and `(auth)` route groups, the booking wizard, both check-in flows, and the admin-app links.
- **WebFrame wrapper** (`components/WebFrame.tsx`) — on viewports ≥768px wide the mobile UI renders inside a 440px centered phone-frame against a deep-green backdrop; below that breakpoint it fills the viewport like a normal mobile web app. No code split — same JS for both.
- **NativeWind** styles, **Reanimated 3** animations, **gesture-handler**, **bottom-sheet**, and **lucide** icons all work on web.

## What does NOT ship to web (and why)

These imports are no-ops or shimmed by `react-native-web`:
- Push notifications, native haptics (haptics gracefully no-op on web)
- Stripe React Native sheets — replace with Stripe.js or Stripe Elements before the real launch
- Native maps and location — `react-native-maps` is web-incompatible; use Google Maps JS API on web
- Camera / `expo-image-picker` — web swaps to a file input automatically

For the MVP demo, the mocked-data path (`EXPO_PUBLIC_USE_MOCKS=true`) means none of the above are exercised on web.

## Environment variables on the host

Copy `.env.example` into the host's environment settings:

```
EXPO_PUBLIC_USE_MOCKS=true
EXPO_PUBLIC_SUPABASE_URL=...
EXPO_PUBLIC_SUPABASE_ANON_KEY=...
EXPO_PUBLIC_STRIPE_PUBLISHABLE_KEY=...
EXPO_PUBLIC_GOOGLE_MAPS_API_KEY=...
```

`EXPO_PUBLIC_*` is the convention Expo uses for variables that should be inlined at build time and exposed to the client bundle.
